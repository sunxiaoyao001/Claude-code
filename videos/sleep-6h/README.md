## 为什么选这个题

- **钩子是反常识的**：大多数人觉得"6 小时也够了"。真实实验告诉你：连续两周只睡 6 小时，注意力测试成绩接近通宵一整晚，**而且本人察觉不到**。前 3 秒就能制造"我也是这样"的代入感。
- **有真实、可查的研究**：宾夕法尼亚大学 Van Dongen 等人 2003 年发表在 *Sleep* 上的 14 天限睡实验，是这个话题被引用最多的研究之一。
- **结尾问题人人能答**："你昨晚睡了几个小时？"——一个数字就能评论，互动门槛极低。
- **画面风格和主题一致**：困倦本身就是"视觉模糊、重影、眼皮打架"，梦境流体风不是装饰，而是在模拟观众的身体感受。

## 0. 快速开始

```bash
cd videos/sleep-6h

# ① 浏览器预览（需要本地 http 服务，图片和 WebGL 不能走 file://）
python3 -m http.server 8080        # 或 npx serve .
# 打开 http://localhost:8080 ，空格播放，S 键显示抖音界面遮挡区

# ② 导出成片 MP4（逐帧渲染，不丢帧）
npm i                              # 安装 playwright（或使用全局 playwright）
node render.mjs                    # → out/sleep-6h.mp4（1080×1920 60fps）
node render.mjs --scale 0.5 --fps 30   # → out/sleep-6h-preview.mp4（快速预览版）
node render.mjs --vo vo.wav        # 混入配音（配乐自动侧链让路）
node render.mjs --stills 3.4,27.6,60.9 # 导出指定时间点的 PNG，用于检查画面
node render.mjs --from 51.2 --to 64    # 只渲染一段
node render.mjs --gpu --jobs 3         # 有独立显卡时：GPU 渲染 + 3 路并行分段
```

## 1. 分镜脚本

时间码精确到 0.1 秒。节奏 75 BPM，1 小节 = 3.2 秒，全片 25 小节，**所有场景切点都落在小节线上**，声画同步。
全片贯穿三个"困倦"母题：**眼皮开合**（片头睁眼、片尾闭眼形成循环，代价段每个镜头末尾"打瞌睡"）、**水波涟漪**（每个关键信息落地时从信息点扩散）、**重影 / 失焦**（主观与现实错位）。
顶部常驻夜间时钟 HUD：从 **01:12 AM · 你还没睡** 走到 **07:00 AM · 天亮了**，片尾变成 **今晚早点睡**。

## 3. 音频设计

### 3.1 配乐（程序化合成，无版权风险）

- **风格**：梦境 lo-fi，C 大调七和弦 / 九和弦，**75 BPM**，四四拍，十六分音符轻摇摆。
- **编制**：FM 电钢琴（Rhodes）、失谐暖 pad、八音盒 / 钢片琴琶音、正弦低音、柔和鼓组（软底鼓 / 刷子军鼓 / 沙锤 / 边击）、全程黑胶底噪（粉噪 + 随机咔嗒）。
- **磁带感**：一个 0.45Hz 慢速 LFO 推动所有合成器的音高（±7 音分），代价段加深到 3.2 倍；59.6–60.6s 整体音高下滑 180 音分，像磁带"掉速"——困到极点。
- **混音**：底鼓侧链轻压 pad / 电钢琴 → 段落低通 → 总线压缩 → 限幅；程序生成的 4.2 秒长混响 + 附点八分延迟；最后峰值归一化到 −1 dBFS（整体响度约 −13.4 LUFS，适合短视频平台）。

| 段落 | 和弦（每小节一个） | 编排 |
|---|---|---|
| 0–6.4 钩子 | Fmaj7 – Em7 | 第 1 小节只有 pad、电钢琴、八音盒，低通 900 → 9000Hz 慢慢打开；第 2 小节鼓组和低音进入 |
| 6.4–19.2 实验 | Dm9 – G6 – Cmaj7 – Am9 | 完整 lo-fi 律动 + 八音盒琶音 |
| 19.2–35.2 反差 | Fmaj7 – Em7 – Dm9 – G6 – Am9 | 去掉八音盒，给曲线留出空间 |
| 35.2–51.2 睡眠债 | Fmaj7 – Em7 – Dm9 – Cmaj7 – Am9 | 八音盒回归，气泡声铺底 |
| 51.2–60.8 代价 | Dm9 – Bbmaj7 – Am9 | 低通压到 2600Hz（隔着一层水）、颤音加深、底鼓加重、心跳；结尾"掉速" |
| 60.8–64 金句 | E7sus | 抽掉鼓和反拍低音，音乐降到 45%，低通 700Hz，只剩 pad 与电钢琴 |
| 64–76.8 解法 | Cmaj7 – Fmaj7 – Am9 – G6 | 低通全开 12kHz，pad 更亮、八音盒更响，颤音收回 |
| 76.8–80 互动 | Fmaj7 | 去鼓，整小节长和弦；78.6s 起低通收回 900Hz，与开场的 Fmaj7 无缝衔接 |

## 4. 技术实现方案

**技术栈**：HTML5 Canvas 2D（场景合成）+ WebGL2（后期着色器）+ Web Audio API（OfflineAudioContext 程序化合成）+ Playwright（无头逐帧渲染）+ ffmpeg（H.264 / AAC 编码）。不依赖任何前端框架，打开浏览器就能跑。

```
           ┌───────────────── renderFrame(t) ──────────────────┐
config.js  │  2D 画布 1080×1920                                 │
 时间线 ──▶│   scenes.js 场景(lt) ── dream.js / draw.js 图元     │
 字幕       │   engine.js 时钟 HUD / 章节条 / 毛玻璃字幕          │
 事件点     │        │                                           │
           │        ▼ 纹理上传                                  │
           │  post.js  WebGL2                                   │
           │   Pass1 液态扭曲·涟漪·重影·镜头·色散（全分辨率）    │
           │   Pass2 高光提取 → 1/4（失焦时另提一份全亮度）       │
           │   Pass3 高斯模糊 1/4 + 1/8（双层辉光 / 景深）        │
           │   Pass4 辉光着色·失焦混合·调色·暗角·颗粒·眼皮遮罩    │
           └──────────────────────┬─────────────────────────────┘
                                  ▼
      预览：requestAnimationFrame + 音频时钟同步（index.html）
      导出：Playwright 逐帧 toDataURL → ffmpeg image2pipe → H.264
音频：audio.js ── OfflineAudioContext 离线渲染 80s ──▶ WAV ──▶ ffmpeg 合成
```

**关键设计**

1. **画面 = f(时间)**：所有动画都由时间 t 推导，随机数来自整数哈希（固定种子），散景 / 浮尘 / 气泡都是解析式运动，没有逐帧累积的状态。因此可以任意拖动、任意顺序逐帧渲染，结果完全一致。
2. **声画同一份时间表**：`config.js` 里的 `EV` 记录关键事件时间点（换句、四个实验组、碰线、日夜循环、快切、金句、卡片……），`scenes.js` 和 `audio.js` 都读它，改一个时间点，画面和音效一起移动。
3. **"睡眠债"是一个模型而不是动画**：`waterAt(t)` 按 5 个日夜循环计算水位——白天涨 0.62，夜里只排回到比前一天高 0.13 的位置——水位、杯底沉淀、日月图标和说明文字都由这个函数推导。
4. **后期参数由场景驱动**：每帧生成一份 `P`（liquid / ripA / ripT / ripC / ghost / defocus / blink / bloomTint……），场景按需叠加冲击包络 `U.hit()` 和 `nod()`（缓慢闭眼、猛地睁开），最后交给着色器。
5. **无缝循环**：片头从眼皮 85% 闭合开始睁开，片尾闭到 85% 并淡入开场画面；配乐首尾都是 Fmaj7 + 900Hz 低通，平台循环播放时听不出接缝。
6. **离线音频加速**：上千个音符和音效不在一开始全部建节点，而是用 `ctx.suspend()` 每 1 秒窗口按需创建，80 秒立体声约 25 秒渲染完。
7. **抗平台二次压缩**：不用细扫描线（避免摩尔纹），导出 BT.709 色彩标记，yuv420p。

## 5. 渲染参数配置

| 参数 | 成片（默认） | 快速预览（`--scale 0.5 --fps 30`） |
|---|---|---|
| 分辨率 | 1080 × 1920（9:16） | 540 × 960 |
| 帧率 | 60 fps（`--fps 30` 可选） | 30 fps |
| 时长 | 80.0 s（4800 帧） | 80.0 s |
| 视频编码 | H.264 High@4.2，CRF 17（发布版用 CRF 16），preset slow，GOP 2 秒，B 帧 2 | CRF 22，preset veryfast |
| 像素格式 / 色彩 | yuv420p，BT.709 | 同左 |
| 音频 | AAC 320 kbps，48 kHz 立体声 | 同左 |
| 封装 | MP4，`+faststart`（便于平台快速加载） | 同左 |
| 中间帧 | JPEG q=0.94 管道传输（`--quality` 可调） | 同左 |
| 渲染速度参考 | 软件渲染（SwiftShader，4 核）约 0.58 秒/帧，1080p60 全片约 47 分钟；本机 GPU 加 `--gpu` 快数倍，GPU 机器上还可加 `--jobs 3` 并行分段渲染 | 约 0.16 秒/帧，80 秒约 6 分钟 |

**体积**：画面有胶片颗粒和散景，压缩效率低，母版有几百 MB。转一个约 28MB、适合直接分享和上传的 1080p 版本：

```bash
V="-vf hqdn3d=1.5:1.5:6:6,fps=30 -c:v libx264 -preset slow -b:v 2600k -pix_fmt yuv420p -g 60"
ffmpeg -i out/sleep-6h.mp4 $V -pass 1 -an -f mp4 /dev/null
ffmpeg -i out/sleep-6h.mp4 $V -pass 2 -c:a aac -b:a 160k -movflags +faststart out/sleep-6h-share.mp4
```

浏览器内"录制 WebM"按钮为实时录制（VP9 + Opus，16 Mbps），方便快速分享；正式发布请用 `render.mjs` 导出 MP4。
