# 研究反哺：与 CLAUDE.md 规格的冲突与修正建议

> **状态：全部按推荐方案通过（2026-10-19），已回写 CLAUDE.md v6。C-16 落地方式：云端默认跑到包体积门禁，`build.sh` 的 preview 段检测到密钥与网络可用才出码，否则明确跳过；人类可本地执行 `./build.sh preview`。**
>
> 规则（CLAUDE.md 11.3）：研究发现与规格冲突时逐条列出并给修正建议，标注 `[待拍板]`，人类确认后回写 CLAUDE.md（本文件各条已改标 `[已通过]`）。
> 严重度：**高** = 合规红线或做不出来；**中** = 按原文实现会出错/返工；**低** = 文案或细节修正。
> 依据详见 `01`–`05` 笔记；"推荐"一栏是我的建议，可直接回复编号 + 同意/改为 xxx。

## 高

### C-01 `[已通过]` Provider C「邀请好友双方各得 24h」= 诱导分享违规（规格 §8、§7.5）
- **冲突**：运营规范把"分享后解锁功能""分享后获得奖励（含虚拟奖品）""邀请好友助力"列为诱导分享，处罚可至封禁；且 `onShareAppMessage` 无分享成功回调、识别"新用户/邀请人"需要后端，与"无账号无后端"矛盾。
- **推荐**：删除邀请奖励机制。冷启动期改为两件合规的事：
  1. **今日限免**：每天轮换 1 台付费相机免费开放（制造每日回访理由，零后端）；冷启动期每日试拍额度 3 → 10 张（`coldStart` 配置项保留，含义改为"慷慨免费层"）。
  2. **同款相机分享卡**：分享卡带 `?pack=<id>` 深链，好友打开直达同款相机；**不给分享者任何奖励、UI 不出现"分享得 xx"文案**（裂变靠内容本身）。
- 解锁抽屉主按钮文案相应改为冷启动期"今日限免：<相机名>" / 变现期"看一段视频 · 解锁 72 小时"。

### C-02 `[已通过]` Provider B「微信支付、仅 Android、iOS 隐藏」已过时且不合规（规格 §8）
- **冲突**：2026-02-27 公告——小程序内虚拟商品（含解锁功能）**必须使用小程序虚拟支付**（`wx.requestVirtualPayment`），**iOS 已开放**（费率约 15%），2026-04-01 起全终端强制；普通 `wx.requestPayment` 卖虚拟商品违规。
- **推荐**：Provider B 改为 `VirtualPaymentProvider`，iOS/Android 都显示入口；**首版不上线支付**（Provider A + 免费层即可提审），代码保留接口与关闭开关。定价 ¥6/¥25 需考虑 iOS 15% / Android 约 1% 通道费。

### C-03 `[已通过]`「不做账号系统、无其他网络请求」与支付不兼容（规格 §8、§9-3）
- **冲突**：虚拟支付的 `paySig`/`signature` 必须服务端用 AppKey + session_key 计算（需 `wx.login`）。
- **推荐**：首版保持零后端；支付上线时引入**微信云开发**（云函数天然拿到 openid、免自建登录，云函数里签名 + 记录权益），隐私指引同步更新。规格措辞改为"首版无后端；变现 B 阶段引入云开发"。

### C-04 `[已通过]` 出片「4000px 长边 ≤ 2.5s」不可预设（规格 §4 性能预算、§2 出片）
- **冲突**：takePhoto 输出分辨率由系统决定，社区实测 `quality:'high'` 在 iPhone 上可低至 720×1280；`'original'` 能否拿到原尺寸待真机；iOS 返回 PNG（大、解码慢）。
- **推荐**：出片长边 = `min(takePhoto 实测长边, 设备档位上限, GL 纹理/渲染缓冲上限)`，档位上限建议 低 2048 / 中 3072 / 高 4096（`getDeviceBenchmarkInfo`）；2.5s 按实测分辨率验收；M1 先跑 01 笔记的测试矩阵再定数值。

## 中

### C-05 `[已通过]` frame-size="medium" 不是 720p（规格 §2）
- 官方：实际像素由系统决定；社区：medium 多为 **480×640**。
- **推荐**：规格改为"≈480×640（系统决定）"；M1 对比 medium / large 的画质与供帧率后定档（全屏取景时 480×640 放大可能偏软）。

### C-06 `[已通过]` LUT 纹理「4096×64」与 33³ 矛盾（规格 §4）
- 4096×64 是 **64³** 的条带尺寸；33³ 条带应为 1089×33。若真用 64³：每款 786KB，3 款免费即 2.36MB，**超过主包 2MB**。
- **推荐**：保留 33³ 二进制（107,811 字节/款，与布局解耦），运行时展开为 **198×198（6×6 瓦片）** 纹理——相比 1089 宽条带对 mediump 坐标精度更友好；shader 见 film-pipeline skill。

### C-07 `[已通过]` Display P3 处理与 `wx.getWindowInfo()` 色域检测不可行（规格 §4）
- `WindowInfo` 无任何色域字段；小程序 WebGL canvas 无 colorSpace 配置。
- **推荐**：全链路 sRGB；LUT 统一以 sRGB in/out 生成；删除该条。

### C-08 `[已通过]` 导出链「离屏 WebGL → canvasToTempFilePath」无文档支持（规格 §2、§3 出片数据流）
- `canvasToTempFilePath` 的 `canvas` 参数文档仅写 `type="2d"` 组件实例；`OffscreenCanvas` 无 `toDataURL`。
- **推荐**：离屏 WebGL → `readPixels` → 2D 画布 `putImageData` + 画日期戳/边框 → `canvasToTempFilePath(jpg, 0.92)`；M2 第一件事做真机 spike（离屏 2D 不行则用页面隐藏 2D canvas）。

### C-09 `[已通过]` 最低基础库 2.30.0 低于隐私接口要求（规格 §1）
- `requirePrivacyAuthorize` / `onNeedPrivacyAuthorization` 需 **≥ 2.32.3**。
- **推荐**：最低基础库定为 **3.0.0**（覆盖面已足够，且可直接用更多新接口）；至少 2.32.3。`getDeviceBenchmarkInfo`（3.4.5）走 `canIUse` 兜底。

### C-13 `[已通过]` 降级判据「预览帧率 < 24fps 关 halation」会误判（规格 §4）
- 相机供帧率由系统决定，可能本身就 < 24fps，与渲染负载无关。
- **推荐**：判据改为"连续 N 帧渲染耗时 > 预算 或 供帧数 − 渲染数 的丢帧率 > 阈值"；启动时用 `getDeviceBenchmarkInfo` 档位决定初始是否开预览 halation。

### C-14 `[已通过]` 本地文件 200MB 总配额未纳入设计（规格 §5、§7.4）
- 用户文件 + 缓存文件合计 ≤ 200MB；资源 LRU 50MB 后照片约剩 150MB（约 75–150 张）。
- **推荐**：相册配额策略——用量 80% 时相册顶部轻提示"已拍 N 张，存到手机后可清理"；资源 LRU 上限按剩余空间动态收缩（50MB → 最低 20MB）。

### C-15 `[已通过]` 颗粒 hash 精度 vs「禁止静态噪点贴图」（规格 §4）
- GLSL ES 1.0 片元 highp 非必备；无 highp 的设备上任何坐标 hash 都会失真。
- **推荐**：有 highp（绝大多数现役机型）→ 无 sin hash 实时生成；无 highp → 降级为"每帧随机偏移/翻转的 256² 噪声纹理"（非静态，仍保留"活"的颗粒）。需确认此降级不违反"禁止静态贴图"的本意。

### C-16 `[已通过]` M0「miniprogram-ci preview 出二维码」在本云端环境无法执行（规格 §12 M0、§14）
- 本容器网络策略拦截 `servicewechat.com`、`*.weixin.qq.com`（代理 403）。
- **推荐（二选一）**：A. 人类在云环境设置中放行这些域名，并在公众平台关闭上传 IP 白名单（云端出口 IP 不固定）；B. 云端只跑 lint/tsc/vitest/包体积检查，`./build.sh preview` 由人类在本地执行。两种都需要真实 AppID + 上传密钥（14.1 人类事项）。

## 低

### C-10 `[已通过]` `wx.vibrateShort` 没有 `success` 类型（规格 §7.6-7）
- 官方：type 仅 `heavy / medium / light`（≥ 2.13.0）。
- **推荐**：快门 heavy / 换机 light / 保存 **medium**（或 light 连振两次模拟"成功"）。

### C-11 `[已通过]` `wx.getSystemInfoSync` 已废弃且无法检测 CSS 能力（规格 §7.2）
- 自 2.20.1 废弃（改用 getDeviceInfo / getWindowInfo / getAppBaseInfo），也无法判断 `backdrop-filter` 是否生效。
- **推荐**：胶卷条默认 `rgba(20,20,22,0.72)` + `backdrop-filter: blur(20px)`；按平台/档位启发式（低档机或已知不支持的环境）切到 `rgba(20,20,22,0.92)` 纯色。

### C-12 `[已通过]` 日期戳字体加载限制（规格 §2、§4）
- `wx.loadFontFace` 只接受 https 或 Data URL，Canvas 2D 需 `scopes: ['native']`。
- **推荐**：日期戳直接用 Canvas 路径绘制**七段数码管**（零字体资产、零许可风险、任意分辨率锐利、无加载失败）；OFL 字体作为备选。

### C-17 `[已通过]`「零 npm 依赖」含义（规格 §2）
- **推荐**：明确为"零**运行时**依赖"；devDependencies 仅 typescript、miniprogram-api-typings、eslint、typescript-eslint、vitest、miniprogram-ci。

### C-18 `[已通过]` 占位 LUT 升级为胶卷 datasheet LUT（规格 §6 占位 LUT 策略）
- spectral_film_lut（MIT）内置胶卷覆盖约 18 款精确 + 8 款近似原型。
- **推荐**：这约 26 款用它离线导出 .cube，其余程序化；Python 只作人工离线工具、不进 CI，产出 .cube 入库。需先验证可脚本化导出。

### C-19 WXSS 无 `:root`（规格 §7.1，实现细则，无需拍板）
- 令牌写 `page { … }`；`--accent` 由页面根节点 `style` 注入。

### C-20 流量主门槛说法不一（规格 §8，信息更新）
- 多数来源 UV ≥ 500，少数仍写 1000；"所有内容只能靠激励视频解锁"的规范原文未能核实。以后台显示为准。

### C-21 supersampler 取帧方式（规格 §12 M4，实现细则）
- 用连续 4 个 onCameraFrame 帧拼 2×2，而非 4 次 takePhoto（太慢）。

### C-23 `[已通过]` 随机元素与「所见即所得」的边界（规格 原则 1、§4 漏光、§6 H 系列）
- 漏光概率、暗房随机工艺、出片颗粒种子都在拍摄瞬间才确定，预览无法 100% 等于成片。
- **推荐**：明确为有意的例外——预览展示"底片基调"（LUT/暗角/光晕/颗粒形态），随机元素只在成片揭晓（保留开盲盒惊喜）；详情页文案说明"每张都有一点不一样"。

### C-22 `[已通过]`「不采集任何数据」表述（规格 §9-2）
- 广告组件由微信提供，非我方可控。
- **推荐**：对外文案改为"照片和取景画面只在你的手机里处理，不上传"。
